## SSL and Proxy Configuration

**Note**: Hydro instances installed using the automated script after 2022-10-27 are pre-configured with **Caddy** by default. You can find the configuration file at `~/.hydro/Caddyfile`.

<Callout type="warn">
### Reverse Proxy Requirements
When using a reverse proxy, your Hydro system settings must be updated to correctly identify client IPs and hostnames:
1. **`server.xff`**: Set this to the header name provided by your proxy (usually `x-forwarded-for`). If incorrect, Hydro will fail to log user IP addresses.
2. **`server.xhost`**: Set this to the header name for the original host (usually `x-forwarded-host`). 
   - **Critical**: Incorrect `server.xhost` settings are a common cause of login failures (e.g., `CsrfTokenError`).
   - If using the one-click installer with Caddy, these are configured automatically. For custom Nginx or HAProxy setups, update these in the Control Panel **before** activation.
</Callout>

### Using Caddy (Recommended)
Caddy automatically manages SSL certificates and is the recommended proxy for Hydro. Below is a sample configuration:

```caddy
# Replace hydro.ac with your domain.
hydro.ac {
  log {
    output file /data/access.log {
      roll_size 1gb
      roll_keep_for 72h
    }
    format json
  }
  
  # Static file serving for performance.
  root * /root/.hydro/static
  @static {
    file {
      try_files {path}
    }
  }
  handle @static {
    file_server
  }
  
  # Main Hydro service.
  handle {
    reverse_proxy http://127.0.0.1:8888
  }
}
```

### Using Nginx
If you prefer Nginx, ensure that **WebSocket proxying** is enabled. Without WebSockets, real-time features like judge updates and the online IDE will not function. Refer to the [Example Configurations](https://github.com/hydro-dev/Hydro/tree/master/examples/reverse_proxy) for Nginx snippets.
